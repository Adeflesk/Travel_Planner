Paste into Claude Code:
Before committing any changes, always run the full CI pipeline locally. Specifically: 1) Run Python linting/type checking with the exact Python version from our CI config (check .github/workflows for the version), 2) Run TypeScript/ESLint checks on the frontend, 3) Run all tests. If anything fails, fix the issues and re-run until all checks pass. Never commit code that hasn't passed the full local CI suite. When fixing CI issues, read the actual workflow YAML first to understand exclusion patterns, Python version constraints, and runner configuration before proposing changes.

Claude can autonomously write a failing test that reproduces the exact bug first, then iterate on the fix until the test passes, and finally run the full suite to catch regressions. This turns every bug into a permanently guarded fix and eliminates the back-and-forth cycle that consumed significant session time.
Getting started: When reporting bugs, ask Claude to write a reproduction test first using your existing test framework, then fix the code iteratively against that test. TodoWrite can track the red-green-refactor cycle.
Paste into Claude Code:
I have a bug to fix: [describe bug]. Before writing any fix, follow this workflow autonomously: 1) Read the relevant source files and existing tests to understand the current behavior, 2) Write a minimal failing test that reproduces exactly this bug, 3) Run the test to confirm it fails for the right reason, 4) Implement the fix, 5) Run the new test to confirm it passes, 6) Run the full test suite to catch any regressions, 7) If anything fails, iterate until all tests pass. Only then present the final changes. Use TodoWrite to track each step.
